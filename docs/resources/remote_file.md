# sysutils_remote_file (Resource)

Downloads an `http` or `https` URL to a local file and verifies its checksum, like Ansible's `get_url` module.

The file is downloaded to a temporary file next to `path` and renamed into place only after its size and checksum have been verified, so `path` never holds partial or unverified content, and a failed download leaves nothing behind. The URL is fetched when the file is created and when it must be downloaded again, never during refresh or plan: drift is detected from the local file alone.

## Example Usage

### Download a release, pinned by its checksum

```terraform
variable "exporter_sha256" {
  description = "SHA-256 of the release tarball, as published next to it."
  type        = string
}

# Download a release tarball, pinned by its published checksum. A download
# that does not match is discarded before it reaches path.
resource "sysutils_remote_file" "exporter" {
  url      = "https://downloads.example.com/exporter/v1.8.2/exporter-1.8.2.linux-amd64.tar.gz"
  path     = "/var/cache/downloads/exporter-1.8.2.linux-amd64.tar.gz"
  checksum = "sha256:${var.exporter_sha256}"
  mode     = "0644"
  owner    = "root"
  group    = "root"
}
```

### A private artifact with an authorization header

```terraform
variable "artifact_token" {
  description = "API token for the artifact repository."
  type        = string
  sensitive   = true
}

variable "agent_sha512" {
  description = "SHA-512 of the agent binary."
  type        = string
}

# A binary from a private artifact repository. The headers are sensitive and
# are sent to artifacts.example.com only, never to a host it redirects to.
resource "sysutils_remote_file" "agent" {
  url      = "https://artifacts.example.com/repository/tools/agent/3.1.0/agent-linux-amd64"
  path     = "/usr/local/bin/agent"
  checksum = "sha512:${var.agent_sha512}"
  mode     = "0755"

  headers = {
    Authorization = "Bearer ${var.artifact_token}"
  }

  timeout        = "5m"
  max_size_bytes = 200 * 1024 * 1024
}
```

### Without a published checksum

```terraform
# Without a published checksum, allow_unverified accepts whatever the server
# returns. The file is downloaded again when url changes or the local copy is
# modified; force_redownload = true would fetch it on every apply.
resource "sysutils_remote_file" "ca_bundle" {
  url              = "https://pki.example.com/internal-ca.pem"
  path             = "/usr/local/share/ca-certificates/internal-ca.crt"
  allow_unverified = true
}
```

To unpack a downloaded archive, pass `path` to the `source` of a [`sysutils_archive_extract`](./archive_extract.md); the [release installation guide](../guides/remote-release.md) shows the whole recipe.

## Schema

### Required

- `path` (String) Absolute path of the local file. Must be in canonical form (no `.`/`..` segments, duplicate or trailing slashes) and must not be `/`. Missing parent directories are created with mode `0755`. A symlink or directory at `path` is refused. Changing this forces a new resource.
- `url` (String) The `http` or `https` URL to download. Must not contain user information (`user:password@`); pass credentials in `headers`. The URL is fetched only when the file is created or must be downloaded again, never during refresh. Changing it downloads again only without `checksum`: with a checksum, the content it pins does not depend on where it comes from.

### Optional

- `allow_unverified` (Boolean) Allow a download without `checksum`. Its content is then whatever the server returns. The file is downloaded again when `url` changes, when the local file no longer has the SHA-256 recorded at the last download, or with `force_redownload`. Defaults to `false`.
- `checksum` (String) Expected checksum of the file, `sha256:<hex>` or `sha512:<hex>`. A download that does not match is discarded before it reaches `path`. Refresh hashes the local file; if it no longer matches, the plan shows its actual checksum being changed back to this value and apply downloads the file again. Required unless `allow_unverified` is `true`.
- `force_redownload` (Boolean) Download the file again on every apply, even if the local file matches. Every plan then shows an update. With `checksum`, the new download must still match it. Defaults to `false`.
- `group` (String) Group name or numeric GID of the file. Requires privileges to change. If unset, a new file gets the group of the user running Terraform, and a replaced file keeps its group.
- `headers` (Map of String, Sensitive) HTTP request headers, such as `Authorization`. The values are sensitive. They are sent to the host of `url` only, and removed from requests that follow a redirect to another host or port.
- `max_size_bytes` (Number) Largest response accepted, in bytes. A larger response, whatever its `Content-Length`, fails the download and leaves nothing behind. Defaults to 1 GiB (`1073741824`).
- `mode` (String) Octal mode with 3 or 4 digits, optionally with a leading zero, such as `"0644"` or `"0755"`. Applied with an explicit `chmod` before the file is renamed into place. Defaults to `"0644"`.
- `owner` (String) Username or numeric UID that should own the file. Requires privileges to change. If unset, a new file belongs to the user running Terraform, and a replaced file keeps its owner.
- `timeout` (String) Maximum time for one download, including redirects and reading the response, as a Go duration such as `"60s"` or `"10m"`. Defaults to `"60s"`.

### Read-Only

- `id` (String) Resource identifier (equal to `path`).
- `sha256` (String) Hex-encoded SHA-256 of the local file. Known at plan time when `checksum` is a SHA-256 checksum, otherwise when no download is planned.

## When the File Is Downloaded

| Situation | Download? |
|-----------|-----------|
| The resource is created and `path` does not exist | Yes |
| The resource is created and `path` already holds a file that matches `checksum` | No; the file is adopted and only its mode and ownership are set |
| The local file no longer matches `checksum` (content drift) | Yes |
| The local file was deleted | Yes; the plan shows the resource being created again |
| `checksum` changes | Only if the local file does not match the new checksum |
| `url` changes and `checksum` is set | No: the checksum pins the content, wherever it comes from |
| Without `checksum`: `url` changes, or the local file no longer has the SHA-256 it had after the last download | Yes |
| `mode`, `owner` or `group` changed on disk or in the configuration | No; they are corrected in place |
| `headers`, `timeout` or `max_size_bytes` change | No |
| `force_redownload = true` | On every apply; every plan shows an update |

A new release on the server is never noticed by itself: with `checksum`, change the checksum (and usually `url`); without one, change `url` or use `force_redownload`.

## Import

An existing file can be imported using its absolute path:

```shell
# The ID is the file's absolute path. url and checksum come from the
# configuration; the next apply records them without downloading the file
# if it matches the checksum.
terraform import sysutils_remote_file.agent /usr/local/bin/agent
```

Import records the file's mode, owner, group and SHA-256. `url` and `checksum` are not known yet, so the next plan shows them being added; if the file matches `checksum`, that apply records them without downloading anything. Terraform 1.5 and later can do both in one apply with an `import` block.

## Drift Detection

On refresh, the provider hashes the local file and reads its mode, owner and group; the URL is not contacted.

- **Content**: if the file no longer matches `checksum`, refresh records the file's actual checksum, with the same algorithm, so the plan shows `checksum` changing from the actual value back to the configured one, and apply downloads the file again. Without `checksum`, a change shows as `sha256` becoming unknown.
- **Mode, owner and group** changed outside Terraform are restored in place. If `owner` or `group` is not configured, its current value is recorded but no change is planned for it.
- A deleted file is removed from state and downloaded again. Anything other than a regular file at `path` fails the refresh.

Equivalent spellings are not drift: a mode of `"644"` matches `0644`, a UID matches its user name, and upper-case hex digits in `checksum` match lower-case ones.

## Security

- **Integrity**: with `checksum`, a download that does not match is discarded, whatever the transport. Plain `http` URLs are therefore safe for integrity when a checksum is set; without one, validation warns about them.
- **Redirects**: at most 10 are followed. A redirect from an `https` URL to anything but `https` is refused, so an attacker who can tamper with a plain-text hop can't substitute content. Configured `headers` are sent only to the host and port of `url`; requests that a redirect sends to another host get none of them, so a token for an artifact repository does not leak to the CDN it redirects to. No `Referer` header is sent either, so a token in the query of `url` stays with its host.
- **Redirects to internal addresses**: a redirect to another host must not lead to a loopback address (including `0.0.0.0`), a link-local address or a cloud metadata service such as `169.254.169.254`, unless the host of `url` itself is one of the same kind. Otherwise a compromised download server could make the provider fetch the cloud instance's credentials or a local service and, without `checksum`, save the answer to `path`. The check applies to the address actually connected to, after DNS resolution. Private addresses (such as `10.0.0.0/8`) are allowed, since internal mirrors often redirect to internal storage. With an `HTTPS_PROXY` or `HTTP_PROXY`, the proxy makes the connections, and it has to enforce such rules itself.
- **Credentials** belong in `headers`, which are sensitive. `url` must not contain `user:password@`, since it is stored in state and shown in plans. Header values are still stored in the state in plain text; protect the state accordingly.
- **Size**: `max_size_bytes` is enforced while the response is read, not only against `Content-Length`, which a server can omit. The response is saved as served: the provider does not request compression, so the checksum applies to the bytes the server publishes, and a compressed response can't expand beyond the limit.
- **TLS** uses the system's trusted CAs, requires TLS 1.2 or later, and honours the `HTTPS_PROXY`, `HTTP_PROXY` and `NO_PROXY` environment variables.
- **The local file**: the temporary file has mode `0600` while it is written. Owner, group and mode are applied through its descriptor after verification, immediately before the atomic rename. A symlink, directory or other non-regular file at `path` is refused and never followed or replaced. Extended attributes of a replaced file, such as a POSIX ACL managed by [`sysutils_file_acl`](./file_acl.md) or an SELinux label, are carried over.

## Caveats

- The target's lock is held only for the rename, not during the download, so a slow download does not block other resources that edit files in the same run. See [Concurrency and Locking](https://registry.terraform.io/providers/blechschmidt/sysutils/latest/docs#concurrency-and-locking).
- Refresh reads the whole local file to hash it, which takes a moment for files of several gigabytes.
- `path` is interpreted inside the provider's [`root_dir`](https://registry.terraform.io/providers/blechschmidt/sysutils/latest/docs#root-directory) if one is set; the download itself always uses the network of the host running Terraform.
- Symlinks in the parent components of `path` are followed. Every ancestor directory must be writable only by trusted users; see the provider's [security model](https://registry.terraform.io/providers/blechschmidt/sysutils/latest/docs#security-model).
