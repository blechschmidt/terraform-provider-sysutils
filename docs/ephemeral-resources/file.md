# sysutils_file (Ephemeral Resource)

Reads a local file, typically a secret, without storing it in the plan or the state. Pass its contents to write-only arguments such as `content_wo` of the `sysutils_file` resource, to provider configuration, or to other ephemeral contexts. The file is read whenever Terraform opens the ephemeral resource, which is during every plan and apply that needs it. Only a regular file that nobody but root or the provider's user can change is read: a symlink at `path` is refused, the file must belong to root or the provider's user and must not be writable by its group or others, and so must every directory on the way to it (sticky directories such as `/tmp` excepted).

An [ephemeral resource](https://developer.hashicorp.com/terraform/language/resources/ephemeral) needs Terraform 1.10 or later, or OpenTofu 1.11 or later. Its values can only be used where Terraform guarantees that they are not stored: in [write-only arguments](https://developer.hashicorp.com/terraform/language/resources/ephemeral#write-only-arguments) such as `content_wo` of [`sysutils_file`](../resources/file.md) (Terraform 1.11 or later, OpenTofu 1.11 or later), in provider configuration, in locals and ephemeral variables and outputs, and in provisioners. Terraform rejects them in ordinary resource arguments.

Unlike the [`sysutils_file` data source](../data-sources/file.md), which stores the contents in the state, this reads the file whenever Terraform needs the value: during every plan and every apply that uses it. The value can therefore differ between plan and apply; since write-only arguments are not part of the plan, that is not an error.

## Example Usage

### Copy a secret into a file of the application

```terraform
# Needs Terraform 1.11 or later, or OpenTofu 1.11 or later, to pass the
# value to a write-only argument. The secret file must belong to root (or
# the user running Terraform) and must not be writable by its group or
# others, and so must every directory on the way to it.
ephemeral "sysutils_file" "db_password" {
  path = "/etc/app/secrets/db-password"
}

# The password is read during plan and apply, written to the file, and
# never stored in the plan or the state. Increase content_wo_version to
# write a changed password.
resource "sysutils_file" "app_env" {
  path               = "/etc/app/app.env"
  content_wo         = "DB_PASSWORD=${trimspace(ephemeral.sysutils_file.db_password.content)}\n"
  content_wo_version = 1
  mode               = "0600"
}
```

### Binary files

```terraform
# A binary key: content is null for files that are not valid UTF-8, so
# pass content_base64 on and decode it again.
ephemeral "sysutils_file" "tls_key" {
  path     = "/etc/app/secrets/tls.key.der"
  max_size = 65536
}

resource "sysutils_file" "tls_key" {
  path               = "/etc/nginx/tls/app.key.der"
  content_wo         = base64decode(ephemeral.sysutils_file.tls_key.content_base64)
  content_wo_version = 1
  mode               = "0600"
}
```

## Schema

### Required

- `path` (String) Absolute path of the file to read. Must be in canonical form (no `.`/`..` segments, duplicate or trailing slashes) and must not be `/`. If the provider's `root_dir` is set, the path is inside it.

### Optional

- `max_size` (Number) Largest file size in bytes to read; a larger file is an error. Defaults to `1048576` (1 MiB); at most `16777216` (16 MiB).

### Read-Only

- `content` (String, Sensitive) File contents as text. Null if the file is not valid UTF-8; use `content_base64` for binary files.
- `content_base64` (String, Sensitive) File contents as standard (padded) base64. Always set, also for text files.
- `sha256` (String) Hex-encoded SHA-256 checksum of the file contents.

## Which files are read

A secret is only as trustworthy as the file it comes from. If another user could write the file, or replace it with a file or symlink of their own, they could feed Terraform a value of their choosing, for example their own SSH key or a password they know. So the file is only read if nobody but root and the user running Terraform can change it:

- `path` itself must not be a symlink, and it must be a regular file. It is opened with `O_NOFOLLOW` and non-blocking, so neither a symlink nor a FIFO planted at `path` is followed or waited on.
- The file must belong to root or the user running Terraform, and must not be writable by its group or by others (`chmod go-w`).
- Every directory on the way to it, including the targets of symlinks in the parent components, must belong to root or the user running Terraform and must not be writable by others. A sticky directory such as `/tmp` is allowed, but then the next component must belong to root or the user running Terraform as well.
- It must not be larger than `max_size`. The ownership, mode and size are checked on the open file, so the file that is read is the file that was checked.

With the provider's [`root_dir`](https://registry.terraform.io/providers/blechschmidt/sysutils/latest/docs#root-directory) set, `path` is inside the root, and symlinks in the tree are resolved as they would be in a chroot; one that leads above the root is an error. The directories of the root itself must then be trusted as described above.

## Errors

| Situation | Diagnostic |
|-----------|------------|
| Nothing exists at `path` (or a parent directory is missing) | `Unable to read file` with "no such file or directory" |
| `path` is a symlink | `Unable to read file` with "is a symbolic link; refusing to follow it" |
| `path` is a directory, FIFO, socket or device | `Unable to read file` with "is not a regular file" |
| The file belongs to another user, or is writable by its group or others | `Unable to read file` with "belongs to user" or "is writable by its group or other users" |
| A directory on the way belongs to another user or is writable by others | `Unable to read file` with "belongs to user" or "is writable by other users" |
| The file is larger than `max_size` | `Unable to read file` with "is larger than max_size" |

## Caveats

- `content` and `content_base64` are sensitive, so Terraform redacts anything derived from them. `sha256` is not, but like every ephemeral value it is never stored.
- The contents are held in memory and sent to Terraform twice (as text and as base64), hence the 16 MiB limit of `max_size`.
- Terraform cannot tell when the file changes. To write a changed secret with `content_wo`, increase `content_wo_version`.
- OpenTofu 1.13.0 plans and applies configurations with ephemeral resources, but `tofu show -json` of a saved plan fails with "no schema found for ephemeral...". Tools that read plans as JSON, such as policy checks, need another OpenTofu version.
