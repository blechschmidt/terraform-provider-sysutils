# sysutils_service (Action)

Restarts, reloads, starts or stops a service when invoked, typically from an `action_trigger` after its configuration file changed. Uses `systemctl` when systemd booted the host and `rc-service` when OpenRC did, like the `sysutils_service` resource. The service must exist when the action runs. Nothing is stored in the state. Requires root privileges and Terraform 1.14 or later.

An [action](https://developer.hashicorp.com/terraform/language/block/action) needs Terraform 1.14 or later. OpenTofu does not support actions and rejects `action` blocks; use `restart_on_change` of the [`sysutils_service` resource](../resources/service.md) there.

Terraform invokes an action when a resource's `action_trigger` fires, for example `after_create` and `after_update` of the [`sysutils_file`](../resources/file.md) holding the service's configuration, or when you run `terraform apply -invoke=action.sysutils_service.<name>`. It never runs when the triggering resource is unchanged, and it leaves nothing in the state.

## Example Usage

### Reload a service after its configuration changes

```terraform
# Reload nginx whenever its site configuration is created or changes. The
# action runs during apply, right after the file is written, and never when
# the file is unchanged.
resource "sysutils_file" "site" {
  path    = "/etc/nginx/conf.d/app.conf"
  content = <<-EOT
    server {
      listen 8080;
      root   /srv/app/public;
    }
  EOT
  mode    = "0644"

  lifecycle {
    action_trigger {
      events  = [after_create, after_update]
      actions = [action.sysutils_service.reload_nginx]
    }
  }
}

action "sysutils_service" "reload_nginx" {
  config {
    name   = "nginx"
    action = "reload"
  }
}
```

### Restart a service when one of several files changes

```terraform
# Restart a service when any of several files change. Each file triggers the
# same action; Terraform invokes it once per changed file.
resource "sysutils_file" "app_config" {
  for_each = {
    "app.env"  = "LISTEN=127.0.0.1:9000\n"
    "app.toml" = "[log]\nlevel = \"info\"\n"
  }

  path    = "/etc/app/${each.key}"
  content = each.value
  mode    = "0640"

  lifecycle {
    action_trigger {
      events  = [after_create, after_update]
      actions = [action.sysutils_service.restart_app]
    }
  }
}

action "sysutils_service" "restart_app" {
  config {
    name    = "app.service"
    action  = "restart"
    timeout = "5m"
  }
}
```

### Invoking it by hand

```shell
terraform apply -invoke=action.sysutils_service.restart_app
```

This runs only the action, without planning any resource changes. Use it to retry an action that failed, or to restart a service on demand.

## Schema

### Required

- `action` (String) What to do: `"restart"` restarts the service, starting it if it is stopped; `"reload"` asks the running service to reload its configuration without restarting, and fails if it is stopped or cannot reload; `"start"` starts it unless it is running; `"stop"` stops it unless it is stopped. With systemd, `restart` runs `systemctl daemon-reload` first, so that changed unit files and drop-ins take effect, and `start` and `reload` do so when systemd reports that the unit's file changed.
- `name` (String) Name of the service. With systemd, a unit name such as `"nginx.service"` or `"nginx"` (short for `nginx.service`); aliases are resolved to the unit they name, and template units such as `"getty@.service"` can only be named by instance. With OpenRC, the name of a script in `/etc/init.d`, such as `"nginx"`.

### Optional

- `timeout` (String) Maximum time each `systemctl` or `rc-service` invocation may take, as a Go duration such as `"30s"` or `"5m"`. Starting, stopping and restarting wait for the service, so this should exceed its own start and stop timeouts. Defaults to `"2m"`.

## Behavior

The init system is detected as for the [`sysutils_service` resource](../resources/service.md#init-system-detection): systemd if it booted the host, otherwise OpenRC. When a plan includes the action, the provider checks that one of them runs the host and that `name` is valid for it, so that a host without either fails the plan before anything changes. When the action runs, it checks that the service exists, and fails with `Service not found` if not.

| `action` | systemd | OpenRC | Afterwards |
|----------|---------|--------|------------|
| `restart` | `systemctl daemon-reload`, then `systemctl restart` | `rc-service <name> restart` | The service must be running |
| `reload` | `systemctl daemon-reload` if the unit file changed (`NeedDaemonReload`), then `systemctl reload` | `rc-service <name> reload` | Not checked; the service keeps running |
| `start` | Nothing if the service is running; otherwise `daemon-reload` if the unit file changed, then `systemctl start` | Nothing if the service is started; otherwise `rc-service <name> start` | The service must be running |
| `stop` | Nothing if the service is stopped; otherwise `systemctl stop` | Nothing if the service is stopped; otherwise `rc-service <name> stop` | The service must be stopped |

`reload` fails with `Service not running` if the service is stopped, since there is nothing to reload; use `restart` if the service may be stopped. It also fails if the service cannot reload: with systemd, a unit needs `ExecReload=`, and with OpenRC, the init script must define a `reload` command in `extra_started_commands`.

A service that stops right after `restart` or `start` fails the action with `Changing service state`. A systemd `Type=oneshot` service needs `RemainAfterExit=yes` to count as running.

## Caveats

- If the action fails, the triggering resource has already been changed and its new state is saved, so the next plan is empty and does not invoke the action again. Fix the cause and run `terraform apply -invoke=action.sysutils_service.<name>`.
- The service must exist when the action runs. If the same configuration installs it, for example with [`sysutils_package`](../resources/package.md), add a `depends_on` on the package to the triggering resource, so that the file is written, and the action invoked, after the installation.
- To keep the service's run state converged as well, combine the action with a `sysutils_service` resource that sets `state = "running"`. The action only acts when it is triggered.
- `before_create` and `before_update` triggers work too, but they run before the file is written, so a restart would still use the old configuration.
- The action changes the running host and is refused when the provider's `root_dir` is set. Use a separate provider configuration without `root_dir` for it.
